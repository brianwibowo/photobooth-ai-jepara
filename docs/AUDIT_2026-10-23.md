# Audit photobooth — 23 Oktober 2026

**Pembaruan UI dan katalog — 27 Oktober 2026:** beranda memakai layout dua
kolom dengan maksimal delapan foto galeri yang bergulir otomatis; alur pilihan
menjadi **Tokoh → Tempat → Foto → Cek foto → Hasil QR**; tempat difilter memakai
`sceneIds` pada tokoh; dan jumlah pengunjung manual dibatasi 1–4. Regression
terakhir lulus: build produksi, 29 tes Node, 18 skenario browser, dan 22 screenshot.

**Koreksi packaging Docker:** audit awal di bawah memakai server lokal, sehingga
tidak mendeteksi `src/config.js` belum disalin ke final image. Dockerfile sudah
diperbaiki dan ditambah gate import server saat build. Tes regresi runtime COPY
berhasil serta mereproduksi kegagalan modul hilang pada susunan lama; jumlah
tes backend/unit sekarang 28. Docker daemon lokal tidak berjalan; belum ada
klaim build/container Linux atau health VPS setelah perbaikan ini.

Refresh sebelumnya menghapus sesi karena seluruh state ada di memori React.
Revisi ini memulihkan sesi aktif pada tab yang sama dan menambahkan pelacakan
generasi agar refresh tidak mengirim proses baru secara otomatis.

Audit aplikasi: **27 tes backend/unit dan 19 skenario browser lulus**. Ada 25
screenshot layout pada 1366×768, 1920×1080, 1080×1920, dan 390×844. Sumber uji
adalah foto sintetis dan kamera/provider/SMTP simulasi. **Tidak ada generasi AI
berbayar atau email nyata pada audit ini.** Status lulus di bawah membuktikan
alur aplikasi, validasi, input provider, dan pemulihan sesi; bukan bukti bahwa
model selalu menjaga jumlah manusia atau kemiripan wajah pada foto final.

## Temuan dan tindakan

| Prioritas | Temuan awal | Hasil akhir |
| --- | --- | --- |
| P0 | Refresh menghapus posisi layar, pilihan, dan foto konfirmasi | Diperbaiki: metadata per tab dan Blob foto lokal dipulihkan; hash isi foto sebelum/sesudah refresh sama. |
| P0 | Refresh saat generasi kehilangan hasil dan dapat mendorong pengulangan berbiaya | Diperbaiki: ID permintaan + fingerprint + status SQLite; polling memulihkan hasil, retry ID sama tidak mengulang provider pada uji positif. |
| P1 | Manual count perlu mengikuti batas konsistensi wajah | Diperbaiki: pilihan cepat 1–4 dan API memakai batas yang sama. Tidak ada default satu orang bila jumlah kosong. |
| P1 | Dua request dapat melewati cooldown bersamaan | Diperbaiki: slot direservasi sebelum menunggu cooldown; request lain ditolak dengan status sibuk. |
| P1 | Kamera terputus atau callback kamera terlambat dapat melanjutkan state yang sudah ditinggalkan | Diperbaiki: invalidasi request, pemeriksaan track/frame, dan pembatalan countdown saat kamera tidak siap. |
| P1 | Status email kembali menjadi formulir kosong setelah refresh | Diperbaiki: status delivery dimuat dari server; job yang sama tidak dikirim ulang. Alamat yang sedang diketik tidak disimpan. |
| P2 | Kontrol grup/form email membuat overflow kecil pada kiosk pendek | Diperbaiki: kolom kamera mencakup dua baris dan jarak aksi hasil dirapikan. |
| P2 | Token admin Unicode dapat berbeda panjang byte dari panjang string | Diperbaiki: panjang byte diperiksa sebelum perbandingan aman; token salah menghasilkan 401. |

Status generasi lengkap dan result disimpan dalam transaksi database yang sama.
Jika server restart ketika request masih berjalan, status ditandai terputus;
tidak ada regenerasi otomatis. Request ID yang dipakai dengan foto atau pilihan
berbeda mendapat 409. Result lewat masa QR + grace tidak dipulihkan.

- Perpanjangan QR hanya sekali, 15 detik lalu langsung home tanpa pop-up ulang;
  status tersimpan di server dan tetap berlaku setelah refresh. Keterangan hasil
  mengikuti tokoh/tempat terpilih. Unduhan PNG dan lampiran JPG memakai nama
  `photobooth_kartini_{nomor_unik}` yang sama, tanpa token QR.

## Skenario positif per jumlah pengunjung pada audit historis

Matriks berikut merekam pengujian saat batas grup masih 20. Regression aktif
setelah perubahan katalog memakai batas manual 1–4; angka 6 dan 8 di bawah tidak
lagi menjadi pilihan UI atau payload valid.

Tokoh pilihan dalam matriks browser adalah Soesalit. Jumlah berikut **tidak
termasuk tokoh**. API juga menguji semua 21 kombinasi tokoh/tempat.

| Pengunjung dalam fixture | Tokoh tambahan | Total yang diminta ke AI | Jumlah manual | Ikuti foto | Refresh seluruh alur |
| --- | --- | --- | --- | --- | --- |
| 1 | 1 | 2 | Lulus | Lulus, tidak dipaksa 1 oleh client | Lulus pada kiosk dan ponsel |
| 3 | 1 | 4 | Lulus | Lulus | Lulus pada kiosk |
| 4 | 1 | 5 | Lulus | Lulus | Lulus pada 1920×1080 |
| 6 | 1 | 7 | Lulus melalui pilihan grup | Lulus | Lulus pada kiosk, portrait, dan ponsel |
| 8 | 1 | 9 | Lulus melalui pilihan grup | Lulus | Lulus pada kiosk |

API menerima batas manual 20; 21 ditolak. Jumlah yang tidak diisi dikirim sebagai
`null` ke generator, bukan diasumsikan satu. Prompt meminta V pengunjung dari
foto sumber + tepat satu tokoh. Ketiga transport provider (Gemini, OpenRouter
images, OpenRouter chat) diuji untuk jumlah kosong, 1, 3, 4, 6, dan 8 pada ketiga
latar: **54 payload input/prompt diperiksa**, dengan sumber dan urutan referensi
yang benar. Ref latar kosong yang hilang ditolak; tidak diganti gambar promosi.

Setiap kasus browser menjalani pilihan kosong → tempat/tokoh terpilih → kamera
→ countdown 7 detik → konfirmasi → generating → hasil → galeri/detail → QR habis
→ perpanjangan 15 detik → reset. Refresh dilakukan pada pilihan, kamera,
konfirmasi, proses berjalan, hasil, galeri/detail, pop-up grace, dan hasil yang
telah diperpanjang. Refresh tidak menambah jatah QR/grace. Countdown kamera
dimulai ulang dengan aksi ambil foto baru; tidak menyelesaikan capture sendiri.

Satu kasus browser tambahan menguji tokoh bernama panjang di gerbang museum,
refresh hasil, serta unduhan PNG asli: nama yang disarankan browser cocok dengan
`photobooth_kartini_{nomor_unik}.png` dari server.

## Skenario negatif aplikasi

| Kondisi | Respons yang diuji | Status |

| Belum memilih tempat atau tokoh | Tombol lanjut nonaktif; tidak mengarang pilihan default | Lulus |
| Jumlah 0, negatif, pecahan, teks, kosong eksplisit, Infinity, atau >20 | 400 sebelum provider dipanggil | Lulus |
| Foto hilang/rusak, MIME tidak didukung, >8 MiB, atau melebihi batas pixel | 400/413/415; tanpa hasil palsu | Lulus |
| ID tokoh/tempat tidak valid; metadata tamu legacy tidak cocok | 400 sebelum provider | Lulus |
| Izin kamera ditolak, kamera tidak ada, izin tak dijawab | Pesan kesalahan; capture nonaktif; dapat kembali | Lulus |
| Kamera terputus saat countdown | Countdown dibatalkan; tidak mengambil frame lama | Lulus |
| Foto cache hilang atau IndexedDB diblokir | Pilihan tetap dipulihkan; kembali ke kamera untuk ambil ulang | Lulus |
| sessionStorage diblokir | Tidak crash/tidak mengirim AI; refresh kembali ke home karena metadata tak tersedia | Lulus sebagai penanganan aman; pemulihan tidak tersedia |
| Snapshot JSON rusak, pilihan invalid, versi lama, sesi idle/terlalu tua | Dibuang tanpa menebak pilihan atau membuka foto lama | Lulus |
| Tab baru atau sesi baru setelah keluar/timeout | Mulai dari home; tidak mengambil alih snapshot tab sebelumnya | Lulus |
| Refresh/koneksi terputus ketika generasi masih berjalan | Status request sama diperiksa; provider tidak dipanggil ulang | Lulus |
| POST selesai tetapi respons menjadi HTML/JSON invalid | Poll status memulihkan hasil; tidak mengirim POST baru otomatis | Lulus |
| Endpoint status gagal setelah refresh | Tampil status koneksi; polling request sama pulih saat jaringan kembali | Lulus |
| Retry request ID sama; ID sama dengan foto/jumlah berbeda | Replay hasil/running; perbedaan payload mendapat 409 | Lulus |
| Server restart ketika request belum selesai | Ditandai terputus; tidak auto-regenerate | Lulus |
| Provider error atau hasil provider bukan gambar | Gagal dengan pesan; kembali ke konfirmasi, foto tetap ada | Lulus |
| Penulisan file hasil gagal | 500; tidak mengembalikan result palsu atau row hasil berhasil | Lulus |
| Request bersamaan saat cooldown; rate limit | 429 sibuk/rate-limited, dengan Retry-After pada rate limit | Lulus |
| Galeri gagal/HTML invalid | Pesan error dan retry; galeri/detail dapat dipulihkan | Lulus |
| Meminta >8 galeri; foto privat/fallback/kedaluwarsa | Hanya delapan terbaru yang memenuhi syarat | Lulus |
| QR habis, lewat grace, token tidak dikenal, atau retensi habis | 404/410; tidak dipulihkan/perpanjang secara diam-diam | Lulus |
| Klik ganda lanjutkan QR | Deadline sama; tidak menumpuk waktu | Lulus |
| Tambahan 15 detik habis setelah refresh | Langsung home tanpa pop-up kedua; server menolak perpanjangan lagi dengan 410 | Lulus |
| Email sudah antre/sent ketika refresh | Status server dipulihkan; bukan mengirim email baru | Lulus dengan SMTP simulasi |
| Email invalid, injection, kuota, restart, retry, timeout ambigu | Ditangani sesuai tes delivery; tanpa kirim ganda otomatis | Lulus dengan SMTP simulasi |
| Token admin kosong/salah/Unicode | 401; ekspor hanya dengan token benar | Lulus |

## Skenario negatif visual AI yang masih terbuka

| Kelompok | Kondisi negatif | Keterbatasan saat ini |
| --- | --- | --- |
| 1 orang | Wajah gelap, filter kuat, wajah terpotong, atau foto tanpa manusia | Belum ada pemeriksa kualitas/detektor wajah; UI tidak otomatis menolak. Hasil AI belum dibuktikan. |
| 3 orang | Satu wajah tertutup pengunjung lain | Belum ada jaminan model mempertahankan identitas/jumlah tiga wajah. |
| 4 orang | Pengunjung di ujung benar-benar di luar frame kamera | Tampilan tidak crop foto, tetapi orang di luar frame sumber tidak dapat dipulihkan dari referensi. |
| >4 orang | Wajah kecil, bertumpuk, jauh, atau jumlah manual salah | Belum ada validasi kecocokan jumlah manual dengan wajah, atau validator jumlah hasil. Model bisa salah. |
| Semua kelompok | Provider menambah/menghilangkan orang atau mengubah wajah | Input kini memakai latar tanpa orang dan prompt membatasi cast; belum ada pemeriksaan visual output otomatis. |

**P1 terbuka: audit AI nyata.** Jalankan sesi nyata 1, 3, 4, 6, dan 8 orang
dengan jumlah manual dan tanpa jumlah. Nilai wajah satu per satu, jumlah total,
ketepatan tokoh/umur/pakaian, lokasi, serta tangan/anatomi. Sertakan satu kasus
wajah tertutup dan pencahayaan buruk untuk tiap kelompok. Tes saat ini tidak
boleh dipakai untuk menyatakan akurasi AI sudah lulus. Deteksi wajah/validator
hasil perlu pekerjaan terpisah jika ingin menahan hasil yang salah otomatis.

**Batas operasional lain:** kamera/printer fisik, browser kiosk terpasang,
ketepatan model/billing provider, serta inbox/spam SMTP nyata belum diverifikasi.
Fallback provider dapat membuat percobaan tambahan; timeout/restart tidak
memberikan jaminan billing exactly-once. Refresh penuh saat browser benar-benar
offline membutuhkan jaringan untuk memuat aplikasi; tidak ada offline/PWA cache.
Jam perangkat diasumsikan tersinkron. Kebijakan rate limit default 8 request
per 10 menit per IP perlu disesuaikan operator dengan kapasitas/budget museum.

## Pemeriksaan VPS dan bukti

Pemeriksaan read-only pada situs produksi: `/api/health` memberi 200/ok,
mode konfigurasi `openrouter+gemini`, dan email belum aktif. Permintaan galeri
`limit=100` memberi delapan item. Ini membuktikan endpoint terjangkau, bukan
validitas saldo/key/provider. Patch pemulihan sesi diaudit lokal; deploy VPS
belum dilakukan oleh agen.

- Ringkasan hasil browser tersimpan di `docs/audit-2026-10-23-results.json`.
- Screenshot sintetis dan laporan mentah berada di `audit-results/` setelah run.
- Jalankan `npm run check`, `npm test`, dan `npm run audit:ui` untuk mengulang.
- Audit UI memerlukan Playwright/Chromium. `PLAYWRIGHT_MODULE_PATH` dapat
  menunjuk runtime modul yang tersedia; `BROWSER_EXECUTABLE` opsional untuk Chrome.
- Test memakai DB/direktori sementara, kamera simulasi, dan callback provider/
  SMTP simulasi; tidak menggunakan gambar pengunjung nyata atau API berbayar.
